## 목표와 범위

팀원 사이트의 디자인과 소개→안내→업무 화면 구조를 기존 Python/Jinja 워크벤치에 반영한다.
카탈로그·시나리오·Run·증빙·검증·비교·공유 모드의 제품 의미를 보존하고, 상세 정보는 필요한 단계에 펼친다.
현재 12개 관리/9개 실행/0개 미실행/3개 대상 없음, N-03 일부 실행, 28개 Run/11개 프로필/652파일을 수용한다.

외부 공개 SaaS의 인증·회사 격리·원격 바인딩, 웹 Run/재테스트/cleanup, WhyYou 수정·새 실제 실행,
법적 인증·상시 감시·AI 모델 품질 검증은 이 Spec의 범위 밖이다.
비작성자 사용성 및 Spec005 전체 마감도 이 문서 작성으로 완료되지 않는다.

## 사용자 흐름과 수용 시나리오

### US1 — 무엇을 확인했는지 빠르게 파악한다

현황에서 네 기준의 목적·범위와 9/0/3을 읽고, N-03 일부 실행을 인지한 뒤 원하는 기준 목록으로 이동한다.
전체 결과를 누르면 기존 검색어 없이 12개가 보인다. A는 기능 부재이고 실패/미완료 진행률로 보이지 않는다.

### US2 — 한 결과의 사실과 근거를 확인한다

시나리오 정의·프로필·전체 실행 목록에서 원래 ID의 Run을 선택한다. 기대·실제 관찰·관련 자료를 읽고 원문/캡처로 이동한다.
N-03은 A1~A3와 U1~U3/L1·후속 조건을 구분하고, N-01은 PC/모바일·측정 v1/v2·정책 식별값을 대조한다.
현재 YAML을 과거 Run의 봉인 관찰처럼 표시하지 않는다.

### US3 — 변경과 한계를 설명한다

child ID로 실제 부모와 비교하고 원본 판정과 변경 원인을 구분한다. H-02 대상 코드 보완과 N-01 측정 보강을 같은 이야기로 만들지 않는다.
보고서에서 전체 범위·버전·증빙·누락·한계를 추적한다. 공유본 열람을 새 실행·현재 READY로 읽지 않는다.
