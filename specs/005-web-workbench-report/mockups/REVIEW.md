# Spec 005 네 화면 목업 검토 (DEMO DATA · MOCK)

- 대상 파일: [workbench-mockup.html](./workbench-mockup.html)
- 근거: Product Brief §7·§10.3·§12, [spec.md](../spec.md)(Clarified 2026-10-08), Decision Log D-018
- 검토자: 태오(UX 검토), 제품 책임자(승인). 승인 뒤 Plan을 시작한다(D-018).
- 모든 실행 ID·SHA-256은 `demo-` 접두어가 붙은 합성 값이다. 실제 Run·판정·증적이 아니다. 화면은 판정을 계산하지 않고 정적 데이터만
  보여 준다. 시나리오 상태는 범위표 그대로다(H-03·E-03·E-02 PASS, E-01 최초 FAIL → 재시험 PASS, N-02 INCONCLUSIVE(A5·A7),
  H-01·H-02·N-01·N-03 NOT_RUN, A-01~A-03 NO_TEST_TARGET).

## 여는 방법

1. 저장소를 받은 뒤 `specs/005-web-workbench-report/mockups/workbench-mockup.html`을 PC 브라우저(Edge·Chrome 등, 창 너비 1024px 이상)로 연다.
   파일을 더블클릭해도 된다. 서버·인터넷·설치가 필요 없다(외부 CDN·폰트·이미지 없음).
2. 화면 맨 위의 빨간 띠 "DEMO DATA · MOCK"는 모든 화면에 고정돼 있다.
3. 상단 탭 ①~④로 네 화면을 오간다. ① 워크벤치의 "상세" 버튼과 ② 시나리오 상세의 E-01·H-01·A-01 전환 버튼도 쓸 수 있다.
4. 확인용 동작: ①의 필터 3개와 "준비 상태 확인"(데모 응답), ②의 명령 "복사", ③의 "실패 규칙만 보기"와 "개발자용 원본 정보 펼치기".

### B. 반드시 구분돼야 할 4쌍

상태는 색만으로 구분하지 않고 아이콘·글자·설명을 함께 쓴다(테두리 모양도 다르다).

| 쌍 | 화면에서의 표현 | 확인 위치 | 결과(O/X) | 의견 |
|---|---|---|---|---|
| 판정 불가 / 미실행 | `?` 점선 테두리 "판정 불가 + 사유 코드" / `○` 점 테두리 "미실행 NOT_RUN" | ① 개수 카드·표·범례, ④ 보고서 요약 | | |
| NO_TEST_TARGET / RUNNER_NOT_READY | `∅` 보라 "대상 없음" / `⚙` 주황 "실행기 미준비" | ① 준비 상태 열, ② A-01·H-01 상세 | | |
| 복구 실패 / 대상 FAIL | `⚠` 짙은 갈색 "복구 실패 RESTORE_FAILED, 실행 안전 문제" / `✖` 빨강 "FAIL" | ③ 무결성 실패 예시 카드, ③ 상단 FAIL | | |
| 최초 실행 / 재시험 | 실행 ID가 다르고 재시험에 "부모" 표시, 부모 불변 확인 | ④ 비교 상단·"부모 기록 불변 확인" | | |

## 의견

### 태오 (UX 검토)

- 검토일: 2026-10-08 (연우 전달)
- 전체 의견: 추천안대로 반영하는 조건으로 승인한다. 반영본은 2026-10-08 목업 수정 커밋이다.
- 꼭 고쳐야 할 것(모두 반영):
  - 4a. 결과 개수는 V4 §8.5 네 범주를 유지한다. 판정 불가 카드 제목은 중립색으로 두고 안에 표와 같은 배지 두 개(노란 `?`
    INSUFFICIENT_EVIDENCE 1 · N-02, 보라 `∅` NO_TEST_TARGET 3 · A-01~A-03)를 둔다. 색으로 세도 글자로 세도 같은 숫자.
  - 4b. 시나리오 표는 통제별로 묶어 통제 이름을 한 번만 쓰고, ID와 버튼은 줄바꿈하지 않는다. 준비 상태 확인 시각은 표 위에 한 번,
    시각이 다른 줄만 따로 표시한다.
  - 4c. 정책 근거에 법 조문을 연결하지 않고 내부 통제 기준과 V4 시나리오 근거만 보인다. "법 조문 대응은 표시하지 않음(법적 준수
    비보증)"을 둔다(V4 §2.2).
  - 4d. PC 전용. 1280px 기준, 1024px까지 깨지지 않는다. 휴대폰·태블릿은 범위 밖.
  - 4e. 비개발자용 기본 문장에서 fixture 이름과 bundle 파일 이름을 빼 개발자용 원본 정보로 옮긴다.
- 있으면 좋은 것: 없음(추가 요청 없음).
