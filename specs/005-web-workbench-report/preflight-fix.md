# 준비 상태 확인 오류 보완 (2026-10-15)

## Specify · Clarify

사용자 요청: 실제 웹의 준비 상태 확인에서 발생하는 오류를 수정하고 화면에서 재확인한다.
Windows 백그라운드 하위 프로세스가 정상 CLI JSON 뒤에
`[0x…] ANOMALY: meaningless REX prefix used`를 출력해 전체 JSON 해석이 실패했다.
또한 현재 열람용 서버에는 새 시험용 환경 설정 8개가 없다. 이를 숨기거나 READY로 표시하지 않는다.

- 알려진 진단 로그만 제거하고 단 하나의 유효한 preflight CLI JSON을 해석한다.
- 임의 로그·Traceback·다중 JSON·잘못된 schema/command/readiness는 계속 오류다.
- `ERROR/CONFIG`는 원본 그대로 보존하며 '시험 환경 설정 필요'와 비민감 다음 조치를 표시한다.
  이것은 준비 상태 enum을 추가하거나 `RUNNER_NOT_READY`로 변환하는 변경이 아니다.
- 실제 사용법 오류·시간 초과·알 수 없는 출력 오류는 계속 '확인 도구 오류'로 표시한다.
- 상태 사전은 기본으로 접어 실제 오류가 없는 화면에서 사전의 오류 예시를 현재 오류로 오독하지 않게 한다.
- 과거 오류 이력·봉인 bundle·판정·READY 기준을 변경하지 않고 새 preflight 기록으로 확인한다.

## Plan · Tasks

- T087: 공통 배지·read model·목록·시나리오에 설정 누락 안내와 조치 표시. 비밀값은 표시하지 않는다.
- T088: 관련 단위·HTTP·브라우저 시험, 실제 두 서버 재시작과 반복 확인, 문서 동기화.

## Analyze

중요 미결정 없음. 새 의존성·환경 자동 탐색·.env 자동 로드·WhyYou Run·시험 환경 자동 기동 없음.
오류 출력을 임의로 성공으로 바꾸지 않는다. 설정 없는 현재 환경의 올바른 결과는 '시험 환경 설정 필요'다.
실제 사용법 오류를 지우는 작업이 아니며 과거 시험 결과와 새 시험 준비 상태의 분리를 유지한다.
