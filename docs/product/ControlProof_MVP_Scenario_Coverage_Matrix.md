# ControlProof MVP 시나리오 범위표

## 1. 이 문서의 역할

이 문서는 “시나리오가 12개 있다”는 말과 “12개를 실제 실행했다”는 말을 분리하는 공식 범위표다.
V4의 12개 시나리오는 모두 제품 카탈로그에서 관리하지만, 2주 MVP에서 실제 실행하는 범위와 실행하지
않는 범위는 서로 다르다.

- 기준일: 2026-10-01
- 적용 결정: Decision Log D-013, D-014
- 제품 주장 범위: `EXECUTED_SCENARIO_AND_EVIDENCE_ONLY`
- 이 표의 상태는 향후 실제 Run과 Spec closure에 맞춰 갱신한다.

## 2. 숫자를 읽는 법

| 구분 | 개수 | 의미 |
|---|---:|---|
| 관리 시나리오 | 12 | 웹 카탈로그와 결과 보고서에서 상태를 보여 줄 전체 목록 |
| 2주 MVP 실제 실행 목표 | 5 | H-03, E-03, N-02, E-01, E-02 |
| MVP에서 `NOT_RUN`으로 표시 | 4 | H-01, H-02, N-01, N-03. 시험 대상은 있으나 이번 범위에서 실행하지 않음 |
| MVP에서 `NO_TEST_TARGET`으로 표시 | 3 | A-01~A-03. WhyYou에 이의제기 기능이 없어 판정 대상 자체가 없음 |

따라서 대외·발표 문구는 다음과 같이 고정한다.

> ControlProof MVP는 12개 시나리오를 한 화면에서 관리한다. 이 가운데 5개는 실제 실행과 증적을
> 제공하고, 4개는 이번 실행 범위 밖인 `NOT_RUN`, 3개는 대상 기능이 없는 `NO_TEST_TARGET`로
> 사실대로 구분한다.

“12개 시나리오 검증 완료”, “12개 시나리오 PASS”, “9개 중 8개 실행”이라고 표현하지 않는다.

## 4. 상태 변경 규칙

1. `NOT_RUN`은 실패도 통과도 아니다. 실제 실행하지 않은 사실을 뜻한다.
2. `NO_TEST_TARGET`은 실행기 미완성이 아니라 대상 서비스에 시험할 기능이 없음을 뜻한다.
3. 실제 실행 시나리오는 actual-stack Run, 필수 assertion, 증적 무결성, 복구 확인과 Validation closure가
   모두 있어야 완료로 바꾼다.
4. Spec 문서나 자동시험만 작성한 상태를 실제 실행 완료로 올리지 않는다.
5. 범위를 확대해 H-01·H-02·N-01·N-03을 실제 실행하려면 별도 Spec 또는 제품 책임자의 명시적 범위
   변경을 Decision Log에 먼저 남긴다.
6. WhyYou에 이의제기 기능이 새로 생기면 A 계열은 자동 PASS가 아니라 `NO_TEST_TARGET`을 해제하고 새
   Spec에서 시험 가능성과 증적 계약을 다시 정의한다.

## 5. 현재 완료율을 말하는 안전한 방식

- 시나리오 카탈로그 기준: 12개 중 12개 처리 방침 확정
- 실제 실행 목표 기준: 5개 중 2개 완료, N-02 actual Run 완료(`INCONCLUSIVE`, 동의 차단·복구는 입증), E-01·E-02 미착수
- 전체 2주 MVP: 미완료

이 세 숫자를 서로 바꾸어 말하지 않는다.
