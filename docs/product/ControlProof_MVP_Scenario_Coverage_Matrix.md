## 1. 이 문서의 역할

이 문서는 “시나리오가 12개 있다”는 말과 “12개를 실제 실행했다”는 말을 분리하는 공식 범위표다.
V4의 12개 시나리오는 모두 제품 카탈로그에서 관리하지만, 2주 MVP에서 실제 실행하는 범위와 실행하지
않는 범위는 서로 다르다.

- 기준일: 2026-10-01
- 적용 결정: Decision Log D-013, D-014
- 제품 주장 범위: `EXECUTED_SCENARIO_AND_EVIDENCE_ONLY`
- 이 표의 상태는 향후 실제 Run과 Spec closure에 맞춰 갱신한다.

| 현재 실제 실행 (D-030 closure 포함) | 9 | N-01, N-02, N-03(일부 범위), H-01, H-02, H-03, E-01, E-02, E-03 |

따라서 대외·발표 문구는 다음과 같이 고정한다.

> ControlProof MVP는 12개 시나리오를 한 화면에서 관리한다. 이 가운데 9개는 실제 실행과 증적을 제공하고(N-03은 정책 교체 주입을 뺀 일부 범위), 3개는 대상 기능이 없는 `NO_TEST_TARGET`로 사실대로 구분한다.

“12개 시나리오 검증 완료”, “12개 시나리오 PASS”, “N-03 전체 검증 완료”라고 표현하지 않는다.

## 4. 상태 변경 규칙

1. `NOT_RUN`은 실패도 통과도 아니다. 실제 실행하지 않은 사실을 뜻한다.
2. `NO_TEST_TARGET`은 실행기 미완성이 아니라 대상 서비스에 시험할 기능이 없음을 뜻한다.
3. 실제 실행 시나리오는 actual-stack Run, 필수 assertion, 증적 무결성, 복구 확인과 Validation closure가
   모두 있어야 완료로 바꾼다.
4. Spec 문서나 자동시험만 작성한 상태를 실제 실행 완료로 올리지 않는다.
5. 범위를 확대해 H-01·H-02·N-01·N-03을 실제 실행하려면 별도 Spec 또는 제품 책임자의 명시적 범위
   변경을 Decision Log에 먼저 남긴다.
6. WhyYou에 이의제기 기능이 새로 생기면 A 계열은 자동 PASS가 아니라 `NO_TEST_TARGET`을 해제하고 새
   Spec에서 시험 가능성과 증적 계약을 다시 정의한다.

과거 2026-10-07 PR 검토 시점에는 복구 시간·A7 재시도 증거·H-03 seed 계약을 자동 검증했고,
보완 후 실제 Run은 `NOT_RUN`으로 남겼다. 이후 2026-10-18 새 actual Run·독립 검증·정리 감사로
